## 1. 项目概述

### 1.1 项目背景
随着 WordPress 在中小企业及个人站长中的广泛使用，用户对网站**速度、稳定性、管理便捷性**的要求越来越高。现有的服务器面板（如宝塔、CyberPanel 等）虽功能全面，但在 WordPress 专项性能优化、全站缓存集成、低成本部署方面仍有提升空间。本项目旨在打造一款**专为 WordPress 设计、以速度为核心、完全免费**的云托管面板，通过深度集成 OpenLiteSpeed + LSAPI + MariaDB + Redis 等技术，实现极致的 WordPress 运行效率。

### 1.2 产品目标
- **极速体验**：从底层到应用层全链路优化，达到 TTFB < 200ms，PageSpeed 移动端评分 ≥ 90。
- **简单易用**：提供一键优化、自动化运维能力，降低用户技术门槛。
- **免费开放**：采用 OpenLiteSpeed、FastAPI、Vue.js 等开源技术栈，无商业授权风险。
- **稳定可靠**：提供完善的监控、备份、安全加固能力，保障站点持续运行。

### 1.3 产品范围
**包含**：
- WordPress 站点一键创建、配置、迁移、备份；
- OpenLiteSpeed 可视化管理及缓存策略配置；
- PHP 多版本及扩展管理、OPcache 深度优化；
- MariaDB 专属优化、慢查询分析；
- Redis 对象缓存集成与监控；
- 四层全站缓存（LSCache + Redis + OPcache + 浏览器缓存）；
- 图片自动化压缩及 WebP/AVIF 转换；
- 前端资源合并压缩、Critical CSS 生成；
- CDN 一键接入及静态资源替换；
- 系统级性能调优与安全加固；
- 实时监控与一键自动化工具。

**不包含**：
- 第三方插件商店；
- 多用户权限体系（初期仅支持单管理员，后续可扩展）；
- 可视化网站编辑器（仅提供标准 WordPress 后台）。

### 1.4 目标用户
- 个人站长、自由职业者
- 中小企业技术运维
- WordPress 开发者与建站公司
- 虚拟主机服务商（可二次开发）

**详细功能点**

### 3.3 OpenLiteSpeed 管理

**概述**  
OpenLiteSpeed（OLS）是面板的底层 Web 服务器，所有性能优化（HTTP/2/3、Brotli、LSCache）均通过 OLS 实现。本模块将复杂的 OLS 配置封装为可视化开关，同时保留配置编辑能力供高级用户使用。

**详细功能需求**

#### 3.3.1 服务状态控制
- **描述**：显示 OLS 运行状态、版本号、PID，提供启动、停止、重启、重载操作。
- **交互设计**：卡片式组件，状态圆点标识，操作按钮组。
- **后端逻辑**：通过 systemd 或 init.d 脚本控制 `lsws` 服务，解析 `openlitespeed --version` 输出。
- **融合策略**：状态监控集成至 Dashboard 及本模块，用户无需手动操作即可知晓服务健康度。

#### 3.3.2 虚拟主机管理
- **描述**：查看所有 OLS 虚拟主机列表，对应面板中的站点。支持修改根目录、域名绑定、日志路径。
- **交互设计**：表格展示主机名、域名、根目录、SSL 状态，行内操作“编辑”“配置预览”。
- **后端逻辑**：读取 OLS 配置目录 `conf/vhosts` 下的虚拟主机配置文件，提供可视化编辑入口。
- **融合策略**：日常用户通过“网站管理”操作站点，本模块仅作为高级查看入口。

#### 3.3.3 LSCache 控制面板
- **描述**：全局 LSCache 开关，缓存存储路径、大小限制，缓存清理策略。
- **交互设计**：开关 + 数字输入框（缓存最大对象数、最大文件大小）。
- **后端逻辑**：修改 OLS 主配置 `lshttpd/lshttpd.conf` 中的 `cache` 相关指令。
- **融合策略**：与缓存中心联动，缓存中心的总开关即控制此处的全局开关。

#### 3.3.4 HTTP/2、HTTP/3、Brotli 压缩开关
- **描述**：一键启用高性能传输协议与压缩算法。
- **交互设计**：三个独立开关，下方显示“建议开启”提示。
- **后端逻辑**：修改 OLS 监听端口的协议参数，添加 `enablehttp3 1`、`enablebrotli 1` 等指令。
- **融合策略**：默认全部开启，用户可出于兼容性关闭。

#### 3.3.5 防盗链、IP 黑白名单、限流
- **描述**：保护站点资源不被非法引用，限制恶意 IP 访问，防止 CC 攻击。
- **交互设计**：表格管理白名单/黑名单 IP 段，输入域配置 Referer 白名单，限流速率（请求/秒）。
- **后端逻辑**：写入 OLS 虚拟主机的 `accessControl`、`bandwidthLimit`、`reqlmt` 配置。
- **融合策略**：提供“快速封禁”按钮，可从监控日志中直接添加 IP。

#### 3.3.6 配置文件可视化编辑
- **描述**：树形或表格形式展示 OLS 主配置及虚拟主机配置，支持修改保存。
- **交互设计**：分层折叠面板，配置项以键值对形式展示，部分关键项增加开关或选择框。
- **后端逻辑**：解析 OLS 配置语法，提供语法校验，写入前自动备份原文件。
- **融合策略**：仅高级用户需要，置于标签页“高级配置”，默认收起。

### 3.4 PHP 管理

**概述**  
PHP 是 WordPress 的运行环境。本模块提供多版本管理、扩展管理、OPcache 优化及 php.ini 可视化配置，全部操作围绕“性能”与“兼容性”展开，默认已应用最优配置。

**详细功能需求**

#### 3.4.1 多 PHP 版本安装与切换
- **描述**：支持 7.4/8.0/8.1/8.2/8.3 版本，可安装多个版本，并为每个站点独立指定版本。
- **交互设计**：版本列表卡片，显示已安装、未安装，安装按钮触发异步任务；站点详情页提供版本下拉切换。
- **后端逻辑**：通过 Remi 或 Sury 源安装对应 `lsphpXX` 包，切换时修改 OLS 虚拟主机的 `extprocessor` 配置。
- **融合策略**：新建站点默认选择最新稳定版，用户无需纠结。

#### 3.4.2 LSAPI 模式管理
- **描述**：显示当前 PHP 处理器类型（LSAPI），并提供进程数、并发数调优。
- **交互设计**：滑块设置 `LSAPI_CHILDREN`（进程数）、`LSAPI_MAX_REQUESTS`（最大请求数）。
- **后端逻辑**：修改 OLS 外部应用配置中的 `maxConnections`、`env` 参数。
- **融合策略**：默认根据服务器内存自动计算推荐值，显示“自动优化”标签。

#### 3.4.3 PHP 扩展管理
- **描述**：一键安装/卸载常用扩展（如 opcache、redis、imagick、exif 等）。
- **交互设计**：扩展列表，每个扩展带开关（已安装/未安装），安装时展示进度。
- **后端逻辑**：调用系统包管理器安装对应 `lsphpXX-ext-*` 包，更新 php.ini 启用扩展。
- **融合策略**：创建 WordPress 站点时自动安装必须扩展（mysqli、redis、opcache）。

#### 3.4.4 OPcache 三套优化模板
- **描述**：提供“极速/稳定/兼容”三套 OPcache 配置预设，一键应用。
- **交互设计**：单选卡片，下方显示各模板核心参数差异。
- **后端逻辑**：修改 php.ini 中 `opcache.*` 相关指令，如 `opcache.memory_consumption`、`opcache.revalidate_freq`。
- **融合策略**：默认启用“极速”模板，用户可在本模块切换。

#### 3.4.5 php.ini 可视化配置
- **描述**：常见参数以表单形式展示（内存限制、上传大小、执行时间、POST 大小）。
- **交互设计**：输入框 + 单位选择，下方提供“恢复默认”按钮。
- **后端逻辑**：更新对应版本的 php.ini 文件，重载 OLS PHP 进程。
- **融合策略**：仅暴露最常用参数，高级参数需通过“编辑原始配置”入口。

#### 3.4.6 错误日志查看与禁用危险函数
- **描述**：实时 tail PHP 错误日志，支持清空、下载；提供禁用危险函数（exec、shell_exec 等）开关。
- **交互设计**：日志窗口（可滚动），禁用函数复选框列表。
- **后端逻辑**：读取 `/usr/local/lsws/lsphpXX/var/log/php_error.log`；在 php.ini 中添加 `disable_functions` 条目。
- **融合策略**：默认禁用高危函数，提升安全性。_

### 3.5 MariaDB 管理

**概述**  
MariaDB 作为 WordPress 数据库引擎，本模块聚焦性能优化、日常维护与迁移兼容。所有操作均封装为“一键优化”“慢查询分析”等业务场景，避免用户直接接触复杂 SQL。

共享数据库实例：一个独立的 MariaDB 数据库，可以被多个 WordPress 站点共用。表前缀生成规则：建议使用 wp_{站点ID}_ ，确保唯一性且易识别。
功能点：
创建共享数据库实例（指定名称、字符集、排序规则）。
为共享实例创建专用数据库用户，或复用现有用户。
查看共享实例下的站点列表（通过 site 表关联）。
删除共享实例（自动将关联站点的 db_mode 切换或阻止删除）。

**详细功能需求**

#### 3.5.1 服务状态监控
- **描述**：显示 MariaDB 运行状态、版本、进程 ID、Uptime。
- **交互设计**：服务状态卡片，操作按钮（启动/停止/重启）。
- **后端逻辑**：通过 systemctl 控制 `mariadb` 服务，执行 `mysqladmin status` 获取信息。

#### 3.5.2 数据库/用户/权限管理
- **描述**：可视化创建/删除数据库、数据库用户，分配权限。
- **交互设计**：列表展示所有库，行内操作用户管理；新建库弹窗同时创建用户。
- **后端逻辑**：执行 `CREATE DATABASE`、`CREATE USER`、`GRANT` 等 SQL。
- **融合策略**：站点创建时自动完成，本模块用于高级管理。

#### 3.5.3 PHPMyAdmin 一键集成
- **描述**：点击按钮在新标签页打开 PHPMyAdmin，自动登录（免密）。
- **交互设计**：按钮“打开 PHPMyAdmin”。
- **后端逻辑**：在本地启动 PHPMyAdmin 容器或已安装实例，传递临时 token 实现自动登录。
- **融合策略**：用户无需记忆数据库密码。

#### 3.5.4 慢查询日志
- **描述**：开启慢查询日志，设置阈值，可视化分析慢 SQL。
- **交互设计**：开关“记录慢查询”，输入阈值（默认 2 秒），下方表格展示慢 SQL 出现次数、平均耗时、示例语句。
- **后端逻辑**：修改 my.cnf 慢查询相关配置，解析慢查询日志文件。
- **融合策略**：提供“一键优化”按钮，根据慢查询推荐索引（高级功能）。

#### 3.5.5 一键优化/修复/清理
- **描述**：对指定数据库执行 `OPTIMIZE TABLE`、`REPAIR TABLE`，清理查询缓存、临时表。
- **交互设计**：下拉选择数据库，点击“开始优化”，显示进度条。
- **后端逻辑**：遍历所有表执行相应 SQL，并执行 `RESET QUERY CACHE`（如开启）。
- **融合策略**：集成到“一键工具”中，也作为独立模块提供。

#### 3.5.6 碎片整理
- **描述**：分析表碎片率，提供碎片整理建议。
- **交互设计**：表格展示表名、数据大小、碎片大小、碎片率，支持勾选整理。
- **后端逻辑**：查询 `information_schema.TABLES` 计算 `data_free`，执行 `OPTIMIZE TABLE`。
- **融合策略**：与一键优化合并，自动识别碎片率 > 30% 的表并提示。

#### 3.5.7 MySQL→MariaDB 迁移工具
- **描述**：检测外部 MySQL 数据库，自动转换引擎、字符集，导入 MariaDB。
- **交互设计**：输入源数据库连接信息，点击“开始迁移”，展示迁移对象列表。
- **后端逻辑**：使用 `mysqldump` 导出 SQL，替换 `ENGINE=MyISAM` 等不兼容语法，通过 `mysql` 导入。
- **融合策略**：作为站点迁移的一部分，也可独立使用。

#### 3.5.8 自动备份
- **描述**：定时备份数据库，支持本地保留份数、远程存储（FTP、云存储）。
- **交互设计**：开关“开启自动备份”，设置周期（每天/每周）、保留数量。
- **后端逻辑**：通过 APScheduler 触发 `mysqldump`，压缩存储，清理过期备份。
- **融合策略**：集成至“备份迁移”模块，此处为数据库专用备份。

### 3.6 Redis 管理

**概述**  
Redis 用于对象缓存，显著降低数据库查询压力。本模块提供一键部署、状态监控、内存配置及对象缓存开关，所有操作均面向“加速”目标。

**详细功能需求**

#### 3.6.1 服务启停与状态监控
- **描述**：显示 Redis 运行状态、版本、内存使用、连接数、命中率。
- **交互设计**：服务状态卡片，启动/停止/重启按钮；实时指标卡片（ECharts 迷你折线图）。
- **后端逻辑**：通过 systemctl 控制 `redis`，执行 `redis-cli INFO` 解析指标。

#### 3.6.2 内存配置
- **描述**：设置 Redis 最大内存使用量及淘汰策略（volatile-lru、allkeys-lru 等）。
- **交互设计**：数字输入框（单位 MB）+ 下拉选择淘汰策略，下方显示建议值。
- **后端逻辑**：修改 redis.conf 中的 `maxmemory` 和 `maxmemory-policy`，重启生效。
- **融合策略**：根据服务器总内存自动计算推荐值（如总内存的 1/4）。

#### 3.6.3 Redis Object Cache 一键部署
- **描述**：为 WordPress 站点启用 Redis 对象缓存，自动安装插件并配置连接。
- **交互设计**：站点详情页或缓存中心“启用 Redis 缓存”开关。
- **后端逻辑**：复制 `object-cache.php` 到 `wp-content` 目录，更新 wp-config.php 添加 `WP_REDIS_CONFIG`。
- **融合策略**：缓存中心开启“对象缓存”即自动执行此操作。

#### 3.6.4 缓存清空
- **描述**：一键清空所有 Redis 数据库（flushall），或指定站点的缓存键。
- **交互设计**：按钮“清空所有缓存”，二次确认；下拉菜单“清空站点缓存”传入站点 ID。
- **后端逻辑**：`redis-cli FLUSHALL` 或使用 `SCAN` 删除匹配前缀的键。
- **融合策略**：与缓存中心“清理对象缓存”联动。

#### 3.6.5 命中率展示
- **描述**：实时显示 Redis 全局命中率（keyspace_hits / (keyspace_hits + keyspace_misses)）。
- **交互设计**：环形进度条，历史命中率曲线（1h/6h/24h）。
- **后端逻辑**：定期轮询 INFO 统计或通过 WebSocket 推送。
- **融合策略**：集成至控制台与 Redis 管理页，直观反映缓存效率。_

#### 3.6.6 多站点隔离
- **描述**：为每个 WordPress 站点分配独立的 Redis 数据库索引（select 1/2/3...），避免键冲突。
- **交互设计**：开关“隔离站点缓存”（默认开启），自动分配数据库 ID。
- **后端逻辑**：修改 wp-config.php 中的 `WP_REDIS_DATABASE` 常量。
- **融合策略**：用户无需关心，自动隔离。

#### 3.6.7 持久化策略（禁用提速）
- **描述**：为追求极致速度，推荐关闭 RDB/AOF 持久化。提供开关“启用持久化”（默认关闭）。
- **交互设计**：开关“持久化数据到磁盘”（开启后性能下降）。
- **后端逻辑**：修改 redis.conf 中 `save` 参数及 `appendonly` 配置。
- **融合策略**：默认关闭持久化，并提示“已为您优化速度”。

### 3.7 图片优化

**概述**  
图片是 WordPress 页面体积的主要贡献者。本模块提供本地化、无 API 依赖的图片压缩与格式转换，支持批量处理与自动优化。所有操作均在面板内完成，不依赖第三方服务。

**详细功能需求**

#### 3.7.1 批量压缩
- **描述**：扫描指定站点的上传目录，对 PNG/JPEG/GIF 进行有损/无损压缩，减少文件大小。
- **交互设计**：选择站点 → 选择压缩强度（无损/普通/极限）→ 开始扫描 → 展示待压缩列表 → 执行压缩。
- **后端逻辑**：调用 `jpegoptim`、`optipng`、`gifsicle` 等工具，支持自定义质量参数。
- **融合策略**：压缩前后大小对比，节省空间可视化。

#### 3.7.2 WebP/AVIF 自动转换
- **描述**：将图片自动转换为 WebP 或 AVIF 格式，并在前端通过 `<picture>` 标签输出。
- **交互设计**：开关“启用 WebP 输出”“启用 AVIF 输出”（需服务器支持）。可设置转换质量。
- **后端逻辑**：安装 `cwebp`、`avifenc`，监控上传钩子实时转换，生成对应格式副本；通过 ModPagespeed 或自定义过滤器替换图片 URL。
- **融合策略**：用户无需改动代码，前端自动输出兼容格式。

#### 3.7.3 懒加载
- **描述**：为所有图片添加 `loading="lazy"` 属性，提升首屏加载速度。
- **交互设计**：开关“开启懒加载”（默认开启）。
- **后端逻辑**：通过 WordPress 过滤器 `wp_get_attachment_image_attributes` 添加属性。
- **融合策略**：无感提升体验。

#### 3.7.4 自适应图片
- **描述**：根据视口宽度输出不同尺寸的图片（响应式），利用 `srcset`。
- **交互设计**：开关“自适应图片”（默认开启）。
- **后端逻辑**：WordPress 默认支持，确保主题正确使用 `the_post_thumbnail` 函数即可。
- **融合策略**：面板确保设置中启用响应式图片。

#### 3.7.5 原图备份
- **描述**：压缩或转换前自动备份原始图片，支持一键恢复。
- **交互设计**：开关“保留原图备份”（默认开启）；图片优化历史记录中提供“恢复原图”按钮。
- **后端逻辑**：将原图移至 `wp-content/uploads/backup` 目录，保留目录结构。
- **融合策略**：防止误操作导致画质损失。

#### 3.7.6 本地化处理引擎
- **描述**：无需 API 密钥，全部在服务器本地执行转换。
- **交互设计**：无 UI 配置，安装时检测依赖并自动安装缺失工具。
- **后端逻辑**：通过 `shutil.which` 检查命令，通过系统包管理器安装。
- **融合策略**：用户零配置。

#### 3.7.7 水印
- **描述**：为图片添加文字或图片水印，支持位置、透明度设置。
- **交互设计**：开关“添加水印”，上传水印图片或输入文字，选择位置。
- **后端逻辑**：使用 `GD` 或 `ImageMagick` 在生成缩略图时合成水印。
- **融合策略**：可选功能，默认关闭。

### 3.8 前端优化

**概述**  
针对 WordPress 前端资源（CSS、JS、字体）进行极致压缩与合并，减少请求数，提升 PageSpeed 分数。本模块将复杂的前端优化技术封装为“一键修复 PageSpeed 问题”功能。

**详细功能需求**

#### 3.8.1 CSS/JS 合并压缩
- **描述**：将多个 CSS/JS 文件合并为单个文件，并去除空白、注释。
- **交互设计**：开关“合并 CSS”“合并 JS”，可选排除列表。
- **后端逻辑**：通过第三方库（如 `matthiasmullie/minify`）在 WordPress 请求时动态生成合并文件并缓存。
- **融合策略**：默认开启，且排除后台、登录页面。

#### 3.8.2 HTML 压缩
- **描述**：去除 HTML 源代码中的空白、注释。
- **交互设计**：开关“压缩 HTML”。
- **后端逻辑**：通过输出缓冲区回调函数压缩 HTML。
- **融合策略**：默认开启。

#### 3.8.3 Critical CSS 自动生成
- **描述**：分析页面首屏内容，提取关键 CSS 内联至 `<head>`，延迟加载非关键 CSS。
- **交互设计**：按钮“生成关键 CSS”，可选择模板（首页、文章页、页面）。
- **后端逻辑**：使用 Puppeteer 或 headless Chrome 渲染页面，使用 Critical 库生成内联样式。
- **融合策略**：耗时较长，异步执行，完成后推送通知。

#### 3.8.4 Google 字体本地化
- **描述**：将主题中调用的 Google Fonts 资源下载到本地服务器，避免跨域请求。
- **交互设计**：开关“本地化 Google 字体”（默认关闭，因版权建议谨慎）。
- **后端逻辑**：扫描 HTML 查找 Google Fonts 链接，下载字体文件并重写 URL。
- **融合策略**：提升国内访问速度，但需注意字体许可。

#### 3.8.5 字体预加载
- **描述**：为本地字体文件添加 `<link rel=preload>`，减少 FOUT/FOIT。
- **交互设计**：开关“预加载字体”。
- **后端逻辑**：在 `wp_head` 中输出预加载标签。
- **融合策略**：建议开启。

#### 3.8.6 延迟加载非关键 JS
- **描述**：为不影响首屏的 JavaScript 添加 `defer` 或 `async`。
- **交互设计**：开关“延迟加载 JS”，可配置关键词白名单（如 `jquery.js` 不延迟）。
- **后端逻辑**：遍历已注册脚本，动态添加属性。
- **融合策略**：默认开启，且自动排除 jQuery、后台脚本。

#### 3.8.7 移除无用 WordPress 资源
- **描述**：移除 Emoji 脚本、Embed 脚本、jQuery Migrate 等冗余代码。
- **交互设计**：复选框列表，用户选择移除项。
- **后端逻辑**：移除对应的 `wp_head` 钩子及脚本注册。
- **融合策略**：默认全部移除，并提供“恢复默认”按钮。

#### 3.8.8 资源版本管理
- **描述**：为静态资源（CSS/JS）添加版本查询字符串，强制客户端更新缓存。
- **交互设计**：开关“静态资源版本化”，版本号自动更新（或手动更新）。
- **后端逻辑**：修改 `style_loader_src` 和 `script_loader_src` 过滤器。
- **融合策略**：配合缓存清理使用。

### 3.9 CDN 接入

**概述**  
一键将站点静态资源（图片、CSS、JS）替换为 CDN 域名，支持主流云厂商及 Cloudflare 自动配置。用户仅需输入 CDN 加速域名或选择服务商授权。

**详细功能需求**

#### 3.9.1 Cloudflare 一键配置
- **描述**：通过 API Token 自动添加域名、设置代理、开启 SSL 等。
- **交互设计**：输入 Cloudflare 邮箱 + API Key（或 Token） → 自动获取域名列表 → 选择需要加速的域名 → 一键配置。
- **后端逻辑**：调用 Cloudflare API v4，创建 DNS 记录，更新 SSL/TLS 模式，激活代理。
- **融合策略**：CDN 零基础用户也能轻松使用。

#### 3.9.2 主流云厂商适配
- **描述**：支持阿里云 CDN、腾讯云 CDN、七牛、又拍云等，提供接入引导。
- **交互设计**：选择厂商 → 输入加速域名、鉴权信息 → 测试连接 → 保存。
- **后端逻辑**：验证 CDN 源站配置是否正确，不直接调用厂商 API（仅提供配置指引）。
- **融合策略**：为高级用户提供手动配置模板。

#### 3.9.3 静态资源自动替换 CDN 地址
- **描述**：将 WordPress 输出的静态资源 URL 前缀替换为 CDN 域名。
- **交互设计**：开关“启用 CDN”，输入 CDN 域名（如 `cdn.example.com`）。
- **后端逻辑**：通过 WordPress 过滤器 `wp_get_attachment_url`、`script_loader_src`、`style_loader_src` 进行字符串替换。
- **融合策略**：支持多站点独立配置。

#### 3.9.4 CDN 缓存清理
- **描述**：在面板清理缓存时，自动向 CDN 厂商发送刷新请求（如支持）。
- **交互设计**：开关“同步清理 CDN 缓存”，需配置 API 凭证。
- **后端逻辑**：调用对应厂商 API 刷新 URL 或目录。
- **融合策略**：仅对已配置厂商生效。

#### 3.9.5 强制 CDN 模式
- **描述**：即使 CDN 回源失败，也不暴露源站 IP（通过修改 OLS 响应头或重定向）。
- **交互设计**：开关“强制 CDN 访问”（需 CDN 支持）。
- **后端逻辑**：在 OLS 虚拟主机中添加条件判断，非 CDN IP 段访问返回 403 或重定向。
- **融合策略**：增强安全性，建议开启。

### 3.10 系统级优化

**概述**  
面板自动检测并优化 Linux 内核参数、服务配置，提升服务器整体处理能力。本模块无直接用户交互，仅在安装时执行，并在控制台提供“应用优化”按钮。

**详细功能需求**

#### 3.10.1 TCP 参数调优
- **描述**：调整 TCP 缓冲区大小、拥塞控制算法（BBR）、TIME_WAIT 复用等。
- **交互设计**：无 UI 或仅展示“已优化”状态。
- **后端逻辑**：修改 `/etc/sysctl.conf`，执行 `sysctl -p`。
- **融合策略**：安装面板时自动执行，用户无感。_

#### 3.10.2 文件句柄提升
- **描述**：增加系统最大文件打开数（`fs.file-max`）及用户进程限制。
- **交互设计**：无 UI 或状态展示。
- **后端逻辑**：修改 `/etc/security/limits.conf` 及 sysctl。
- **融合策略**：提升 OLS 并发能力。

#### 3.10.3 Swap 优化
- **描述**：调整 swappiness 值（推荐 10），减少磁盘 I/O。
- **交互设计**：无 UI 或状态展示。
- **后端逻辑**：修改 `/etc/sysctl.conf` 中的 `vm.swappiness`。
- **融合策略**：默认优化。

#### 3.10.4 磁盘 I/O 调度
- **描述**：针对 SSD 设置 `none` 或 `noop` 调度器，针对 HDD 设置 `deadline`。
- **交互设计**：无 UI 或状态展示。
- **后端逻辑**：检测磁盘类型，修改 `/sys/block/*/queue/scheduler`，并写入 udev 规则持久化。
- **融合策略**：自动适配。

#### 3.10.5 内核参数优化
- **描述**：调整网络连接跟踪、虚拟内存等参数，提升高并发稳定性。
- **交互设计**：无 UI 或状态展示。
- **后端逻辑**：写入 sysctl 配置集。
- **融合策略**：预设一套经过测试的参数模板。

#### 3.10.6 时间同步
- **描述**：安装并启用 NTP 服务，确保服务器时间准确。
- **交互设计**：开关“自动同步时间”（默认开启）。
- **后端逻辑**：安装 `chrony` 或 `ntp`，配置并启动。
- **融合策略**：避免因时间错误导致 SSL 证书问题。

#### 3.10.7 禁用无用系统服务
- **描述**：关闭不需要的系统服务（如 cups、bluetooth、postfix 等），释放内存。
- **交互设计**：列表展示可禁用的服务，复选框选择，点击“禁用”。
- **后端逻辑**：`systemctl disable --now`。
- **融合策略**：默认仅禁用明显无用的服务，提供用户手动选择列表。

### 3.11 安全加固

**概述**  
从面板、Web 服务器、WordPress 三个层面提供安全防护策略，所有功能以“开关”形式呈现，用户可一键开启主流安全配置。

**详细功能需求**

#### 3.11.1 防火墙端口管控
- **描述**：限制仅开放必要端口（22、80、443、面板端口），支持 IP 白名单。
- **交互设计**：端口列表表格，开关“启用防火墙”，添加/删除允许端口，限制 IP。
- **后端逻辑**：操作 `firewalld` 或 `iptables`，备份原规则。
- **融合策略**：面板安装时默认开启，仅允许 SSH、Web 及面板端口。

#### 3.11.2 后台路径隐藏
- **描述**：修改 WordPress 默认后台路径 `/wp-admin` 为自定义字符串。
- **交互设计**：输入框“后台登录地址”（如 `my-secret-login`），按钮“立即修改”。
- **后端逻辑**：通过 WordPress 插件或 `wp-admin` 重写规则，同时修改 `.htaccess` 或 OLS 重写规则。
- **融合策略**：有效防止暴力破解，默认不开启（用户需手动启用）。

#### 3.11.3 防暴力破解
- **描述**：限制登录失败次数，临时封禁 IP。
- **交互设计**：开关“登录保护”，设置最大尝试次数、封禁时间。
- **后端逻辑**：通过 WordPress 插件（如 WP Limit Login Attempts）或 OLS 限流模块实现。
- **融合策略**：推荐开启。

#### 3.11.4 目录浏览禁止
- **描述**：禁止访问网站目录下无索引文件的文件夹。
- **交互设计**：开关“禁止目录浏览”（默认开启）。
- **后端逻辑**：在 OLS 虚拟主机配置中添加 `autoindex off`。
- **融合策略**：基础安全配置。

#### 3.11.5 恶意 IP 封禁
- **描述**：根据 fail2ban 日志或自定义列表自动封禁恶意 IP。
- **交互设计**：展示已封禁 IP 列表，支持手动添加/解封。
- **后端逻辑**：集成 fail2ban，配置 jail 保护 SSH、WordPress 登录等，或直接操作防火墙。
- **融合策略**：自动化运维。

#### 3.11.6 文件权限修复
- **描述**：将 WordPress 文件权限恢复为安全建议值（目录 755、文件 644、wp-config.php 600）。
- **交互设计**：按钮“修复文件权限”。
- **后端逻辑**：递归 `chmod`、`chown` 操作。
- **融合策略**：提供快速修复能力。

#### 3.11.7 XML-RPC 关闭
- **描述**：禁用 WordPress XML-RPC 功能，避免 DDoS 攻击及暴力破解。
- **交互设计**：开关“关闭 XML-RPC”（默认开启）。
- **后端逻辑**：添加过滤器 `add_filter('xmlrpc_enabled', '__return_false')`，或通过 OLS 屏蔽 `xmlrpc.php`。
- **融合策略**：增强安全，且不影响绝大多数现代站点。

#### 3.11.8 WP 版本隐藏
- **描述**：移除 WordPress 版本号输出，减少指纹暴露。
- **交互设计**：开关“隐藏版本号”（默认开启）。
- **后端逻辑**：移除 `wp_generator` 标签，以及样式/脚本中的版本号。
- **融合策略**：常规安全实践。

### 3.12 备份与迁移

**概述**  
提供全站（文件+数据库）的备份、恢复及外部面板迁移能力。备份可定时执行，迁移支持从宝塔、CyberPanel 等常见面板导入站点。

**详细功能需求**

#### 3.12.1 全站备份/恢复
- **描述**：手动或定时备份整个网站目录及数据库，生成压缩包。
- **交互设计**：备份列表展示文件名、大小、创建时间，支持下载、删除、恢复。
- **后端逻辑**：使用 `zip` 或 `tar` 打包网站目录，同时 `mysqldump` 导出 SQL，合并为一个文件。
- **融合策略**：恢复时可选择覆盖文件、数据库或两者。
- 提供备份范围选项：仅备份此站点（默认）、备份整个共享数据库（管理员权限）。

#### 3.12.2 定时备份策略
- **描述**：按日/周/月自动备份，保留最近 N 份，支持备份到远程存储（FTP、阿里云OSS、S3）。
- **交互设计**：开关“启用定时备份”，选择周期、保留份数、存储位置。
- **后端逻辑**：APScheduler 触发备份任务，完成后上传远程。
- **融合策略**：关键数据的最后防线。

#### 3.12.3 一键迁移（外部面板迁入）
- **描述**：从宝塔、CyberPanel、Plesk 等面板导出的备份文件一键解析并还原。
- **交互设计**：上传备份包 → 选择原面板类型 → 开始迁移。
- **后端逻辑**：根据不同面板的备份结构，解析数据库配置、域名信息，重新部署到当前环境，将原数据库表迁移至共享数据库，并重命名表前缀为符合新站点规则的值。。
- **融合策略**：吸引其他面板用户的核心功能。

#### 3.12.4 站点复制（Staging）
- **描述**：复制现有站点到子目录或子域名，用于测试更新或改版。
- **交互设计**：选择源站点 → 输入目标域名或目录 → 点击复制。
- **后端逻辑**：复制文件，创建新数据库并导入数据，替换配置中的 URL 信息。
- **融合策略**：方便开发测试。

### 3.13 监控中心

**概述**  
实时展示服务器资源、Web 服务、缓存性能等多维度指标，通过图表让用户直观感知“快”与“稳”。支持历史数据回溯与异常报警。

**详细功能需求**

#### 3.13.1 CPU/内存/磁盘/流量实时曲线
- **描述**：ECharts 面积图，1/6/24 小时时间粒度，支持平滑刷新。
- **交互设计**：标签页切换不同指标，鼠标悬停显示详细数值。
- **后端逻辑**：WebSocket 每秒推送最新数据，历史数据从时序数据库（或本地文件）读取。
- **融合策略**：集成至控制台，点击进入全屏监控中心。
- 监控告警：增加对共享数据库表总数的监控，超过阈值（如5000张表）时提醒用户新增共享实例。

#### 3.13.2 Web 请求量统计
- **描述**：显示 OLS 处理的请求总数、QPS、响应状态码分布。
- **交互设计**：折线图展示 QPS，饼图展示状态码比例（2xx/3xx/4xx/5xx）。
- **后端逻辑**：解析 OLS 访问日志（或使用 RTMP 统计），聚合计算。
- **融合策略**：需开启 OLS 访问日志。

#### 3.13.3 数据库查询耗时
- **描述**：展示 MariaDB 平均查询耗时、慢查询数量趋势。
- **交互设计**：折线图，可关联慢查询日志列表。
- **后端逻辑**：查询 `performance_schema` 或解析慢查询日志。
- **融合策略**：帮助定位数据库瓶颈。

#### 3.13.4 Redis 命中率
- **描述**：实时及历史命中率曲线。
- **交互设计**：环形图 + 折线图。
- **后端逻辑**：轮询 Redis INFO 命令。
- **融合策略**：缓存效率可视化。

#### 3.13.5 缓存命中率（LSCache）
- **描述**：显示 LSCache 页面缓存命中率。
- **交互设计**：环形图 + 折线图。
- **后端逻辑**：解析 OLS 日志中 `X-LiteSpeed-Cache: hit/miss` 标识。
- **融合策略**：需 OLS 记录缓存 HIT 日志。

#### 3.13.6 TTFB 监控
- **描述**：模拟访问站点，测量首字节时间。
- **交互设计**：折线图展示 TTFB 变化趋势。
- **后端逻辑**：定时任务使用 cURL 采集各站点 TTFB，存入数据库。
- **融合策略**：直接反映优化效果。

#### 3.13.7 PageSpeed 评分检测
- **描述**：调用 Google PageSpeed Insights API 获取移动/桌面端评分，并记录历史。
- **交互设计**：展示最新评分，趋势图，下方列出优化建议。
- **后端逻辑**：定时任务或手动触发检测，存储评分历史。
- **融合策略**：通过前端优化模块直接修复问题。

### 3.14 一键工具（超级卖点）

**概述**  
将多个优化、修复步骤组合为一个原子化操作，用户点击即可完成全链路加速或故障恢复。所有工具均以卡片形式陈列在独立页面或控制台快捷区域。

**详细功能需求**

#### 3.14.1 一键全站极速优化
- **描述**：执行预设的最佳性能组合：开启四层缓存、图片批量转 WebP、合并压缩 CSS/JS、生成 Critical CSS、OPcache 极速模板、数据库优化、清理 transient。
- **交互设计**：大号按钮“⚡ 一键极速优化”，点击后展示进度条，完成后显示报告（节省空间、评分提升）。
- **后端逻辑**：串行调用各模块接口，记录每一步耗时，汇总结果。
- **融合策略**：面板最核心的“傻瓜式”优化入口。

#### 3.14.2 一键环境修复
- **描述**：检测 OLS、MariaDB、Redis 服务状态，异常则重启；修复文件权限；重置缓存配置为推荐值。
- **交互设计**：按钮“🔧 环境修复”，执行后显示各服务状态变化。
- **后端逻辑**：依次调用服务状态检测与修复脚本。
- **融合策略**：用户遇到网站无法访问时的首选自救手段。

#### 3.14.3 一键清理垃圾
- **描述**：清理所有站点的修订版本、草稿、垃圾评论、过期 transient、回收站文章。
- **交互设计**：按钮“🗑️ 清理垃圾”，执行前可勾选要清理的内容类型。
- **后端逻辑**：对每个 WordPress 站点执行 SQL 删除操作。
- **融合策略**：数据库瘦身，提升备份恢复速度。
- 垃圾数据清理（修订版本、草稿）需在共享库中针对特定站点的表执行 SQL。

#### 3.14.4 一键数据库优化
- **描述**：对所有数据表执行 OPTIMIZE 和 REPAIR。
- **交互设计**：按钮“📊 数据库优化”，显示进度。
- **后端逻辑**：遍历所有数据库表执行优化 SQL。
- **融合策略**：独立快捷操作。
- 数据库优化（OPTIMIZE/REPAIR）需支持按站点执行，仅操作该站点前缀的表。

#### 3.14.5 一键重置权限
- **描述**：将所有站点目录及文件权限重置为安全推荐值。
- **交互设计**：按钮“🔐 重置权限”，确认弹窗。
- **后端逻辑**：递归 chmod/chown。
- **融合策略**：解决文件上传、插件安装权限问题。

#### 3.14.6 一键修复故障
- **描述**：尝试自动修复常见 WordPress 问题（白屏、内存耗尽、插件冲突等）。
- **交互设计**：按钮“🚑 修复故障”，执行诊断脚本。
- **后端逻辑**：切换主题、禁用所有插件、增加 WP_MEMORY_LIMIT 等。
- **融合策略**：适合初级用户。

#### 3.14.7 一键升级环境
- **描述**：升级 OLS、MariaDB、Redis、PHP 等核心组件到最新稳定版（需确认兼容性）。
- **交互设计**：按钮“⬆️ 升级环境”，列出可升级组件，用户勾选后执行。
- **后端逻辑**：通过官方源升级软件包。
- **融合策略**：保证面板运行环境安全。

#### 3.14.8 一键生成测速报告
- **描述**：选择站点 → 系统自动进行 PageSpeed 检测、TTFB 测量、缓存命中分析，生成 PDF 报告。
- **交互设计**：按钮“📄 生成报告”，选择站点，预览报告后下载。
- **后端逻辑**：采集多维度数据，使用 WeasyPrint 或 wkhtmltopdf 渲染为 PDF。
- **融合策略**：用户可向客户展示优化成果。

## 5. 技术架构

### 5.1 总体架构
```
[用户浏览器] → [Vue.js 前端] → [FastAPI 后端] → [系统服务/命令] → [OpenLiteSpeed/PHP/MySQL/Redis]
         ↑__________WebSocket 实时状态___________↑
```
- 前后端完全分离，RESTful API + WebSocket。
- 后端通过 Subprocess/Systemd 控制底层服务，避免重写复杂配置逻辑。

### 5.2 技术栈明细
| 层级     | 选型                                                         | 说明                           |
|----------|--------------------------------------------------------------|--------------------------------|
| 前端     | Vue 3 + Vite + Arco Design Vue + Pinia + Axios + ECharts    | 轻量、快速、美观              |
| 后端     | Python 3.10+ / FastAPI + Uvicorn + Gunicorn                 | 高性能、自动生成 OpenAPI 文档 |
| 系统交互 | SSH(paramiko) / subprocess / Systemd                        | 非侵入式服务管理              |
| 数据库   | MariaDB + PyMySQL                                           | 稳定、兼容 MySQL              |
| 缓存     | Redis 7+ + redis-py                                         | 对象缓存                     |
| Web 服务器 | OpenLiteSpeed + LSAPI                                       | 高性能、免费、WP 友好         |
| 定时任务 | APScheduler                                                 | 备份、优化任务               |

### 5.3 前后端交互规范
**统一返回格式**
```json
{
  "code": 200,        // 0 为成功，非0为错误码
  "msg": "success",   // 提示信息
  "data": {}          // 业务数据
}
```

**认证方式**
- Header: `Authorization: Bearer <jwt_token>`
- Token 有效期默认 24 小时，可配置。

**实时通信**
- WebSocket 路径: `ws://{panel_ip}:{port}/ws/system`
- 推送频率：1次/秒，数据包含 CPU、内存、磁盘 IO、服务状态。

**接口文档**
- FastAPI 自动生成 Swagger UI: `http://{panel_ip}:{port}/docs`
